# Networking Portfolio

A portfolio for demonstrating networking knowledge through clear explanations, reproducible configurations, and evidence of work. This repository is a starting scaffold; no completed projects, certifications, professional experience, or measured results are claimed here.

## Featured work

When work is complete, replace this guidance with links to **2–3 completed projects** in `projects/`. For each, include a short problem statement, your contribution, and a result supported by a test or other evidence. Until then, leave this section as guidance rather than presenting planned work as finished.

Suggested entry format:

> **[Completed project title](projects/your-project/README.md)** — Problem addressed; what you built; verified outcome; link to evidence. State whether it was a lab, simulation, personal deployment, or authorized real-world work.

## Scope and evidence

Cover networking topics you can explain and demonstrate, such as switching, routing, addressing, network services, security controls, and diagnostics. Choose entries for their quality and relevance rather than their number.

- Label every entry with its context and status: for example, **simulated lab — in progress** or **personal deployment — complete**. Describe completion criteria before claiming completion.
- Distinguish your work from a tutorial, team contribution, or vendor example. Cite sources and explain your own decisions.
- Record expected and actual behavior, including failures and limitations. Do not imply production experience or scale from a simulation.
- Use sanitized configurations, diagrams, command output, and test tables as evidence. Identify illustrative output explicitly; never present it as a captured result.
- Publish only material you own or have permission to share. Remove credentials, keys, personal data, client/employer information, and sensitive network details before adding files to Git.

## Adding work

1. Read the appropriate section README.
2. Create a descriptive folder, such as `labs/<topic>/` or `projects/<project-name>/`.
3. Copy a template into that folder as `README.md`, then replace its prompts with facts. Mark unknowns and unfinished tests clearly.
4. Put sanitized supporting files beside the README and link them using relative paths. Keep large or raw captures out unless needed and safe to share.
5. Add a descriptive link to the section README. Feature a project on this page only after its completion criteria are met.

Keep documentation readable for a recruiter at the top and technically reviewable in the details. Commands and screenshots should support an explanation, not replace it.
