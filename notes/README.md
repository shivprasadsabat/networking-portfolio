# Notes

Use this section for concise networking explanations and reusable reference notes. There are no notes yet.

## Add

Create a clearly titled Markdown file or topic folder. Start with the question or concept, explain it in your own words, show a small labeled example, and identify assumptions and platform/version limits. Link authoritative references with access dates or versions. For commands, explain purpose, where they run, and any operational effect.

State whether an example is illustrative or was actually tested. Link related projects, labs, or diagnostic cases when they provide evidence. Add each note here with a one-line description and update or review date.

## Keep out

Do not add copied course material, exam dumps, unsupported claims, personal reminders, secrets, or employer/customer documentation. Full exercises belong in [labs](../labs/README.md); completed implementations belong in [projects](../projects/README.md). Keep personal planning outside tracked portfolio content.
